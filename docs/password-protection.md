# 密码保护指南

[返回项目首页](../README.md) · [配置说明](configuration.md) · [English Guide](password-protection.en.md)

## 选择保护方式

| 保护范围 | 配置位置 | 适用场景与行为说明 |
| --- | --- | --- |
| **全站文章 / 页面** | 主题设置「全站加密密码」（`postPassword`） | 为所有未配置更高优先级密码的文章和独立页面提供统一的兜底门禁 |
| **指定分类** | 主题设置「加密分类」与「分类独立密码设置」 | 让同一分类下的文章共享密码，或为不同分类分配各自独立的密码 |
| **单篇文章 / 页面** | 编辑器自定义字段 `password` | 为特定文章或页面设置专属密码，优先级高于分类密码与全站密码 |
| **正文内联段落** | 正文标记 `{password:密码}...{/password}` | 保持文章整体公开，仅对正文中的特定段落、图片或代码块进行加密 |

- **页面级密码优先级**：**单篇自定义字段 `password` ＞ 分类独立密码 ＞ 全站加密密码**。
- **内联段落独立校验**：正文中 `{password:...}` 标记的密码块与页面级门禁相互独立；若文章同时存在页面级密码与内联密码，访客需先通过页面门禁，再单独解锁目标段落。

## 分类密码配置

1. 登录 Typecho 后台，进入 **「控制台 → 外观 → 设置外观」**。
2. 在 **「加密分类 (用英文逗号分隔)」** 中填写分类的**缩略名（`slug`）**，例如：`private,secret,vip`。
3. 在 **「分类独立密码设置」** 中按 `分类slug:密码` 的格式每行填写一条规则：

   ```text
   private:your-private-password
   secret:your-secret-password
   vip:your-vip-password
   ```

4. 按需设置「加密分类文章在首页的显示」、「加密分类的归档页面是否需要密码验证」及「RSS/Atom 订阅源中的加密文章」。

> **配置细节说明**：
> - 请务必填写分类的**缩略名（`slug`）**而非分类显示名称。
> - 凡在「分类独立密码设置」中配置了密码的分类，即使未写入上方的「加密分类」逗号列表，也会自动被识别为受保护分类。
> - 每行规则仅按**第一个英文冒号 `:`** 拆分缩略名与密码，因此密码本身可以包含冒号；行首尾的多余空白会被自动修剪。

### 全站密码与分类密码的关系

- 若某个分类被列入了「加密分类」，但未在「分类独立密码设置」中指定独立密码，该分类会自动回退使用「全站加密密码」。若此时全站密码也为空，该分类将保持锁定状态（无法通过密码验证），直至管理员补全密码配置。
- **重要提示**：一旦填写了「全站加密密码」，**所有未配置分类密码或单篇密码的普通文章和页面也会被加密**。如果您只希望让若干个指定分类共享同一个密码，而保持其余分类公开，请将「全站加密密码」留空，并在「分类独立密码设置」中为这几个分类分别填入相同的密码。

### 首页列表、分类归档与摘要表现

| 配置项 / 状态 | 前台行为表现 |
| --- | --- |
| **首页显示：显示（默认）** | 首页列表正常展示受保护分类下的文章卡片，未解锁时摘要替换为密码保护提示 |
| **首页显示：隐藏** | 在首页 SQL 查询层直接排除受保护分类下的文章（即使访客已解锁该分类，首页列表也不会重新混入） |
| **分类归档密码：需要（默认）** | 访问受保护分类归档页（`/category/{slug}/`）时，须先输入该分类密码才能查看文章列表 |
| **分类归档密码：不需要** | 公开展示分类归档页的文章列表；但未解锁文章的摘要与正文依然保持受保护状态 |
| **访客已解锁对应密码** | 列表页可展示该文章的正常文本摘要（正文中的 `{password:...}` 与 `{hide}` 内联块仍会从摘要中剥离） |

- 分类归档页与使用该分类密码的文章**共享解锁状态**（解锁一次即可同时浏览分类列表与分类内文章）。
- 若分类内的某篇文章额外设置了自定义字段 `password`，则解锁分类不会自动解锁该文章，访问该文章时仍需验证其专属字段密码。

## 单篇文章与页面密码

在文章或独立页面编辑器底部的 **「自定义字段」** 区域添加如下字段：

| 字段属性 | 填写值示例 |
| --- | --- |
| **字段名称** | `password` |
| **字段类型** | 字符（文本） |
| **字段值** | `your-entry-password` |

- 默认独立页面（`page.php`）、时间轴归档（`page-archive.php`）与友情链接（`page-links.php`）均遵循相同的页面级密码门禁。
- 例如：某篇文章归属于密码为 `cat-pass` 的 `private` 分类，同时设置了自定义字段 `password = post-pass`，则访问该文章时以 `post-pass` 为准。
- 主题的 `password` 自定义字段与 Typecho 编辑器自带的「公开度 → 密码保护」原生密码相互独立。关于时间轴归档对原生密码文章的排除策略，请参阅 [内容与页面用法](usage.md#时间轴归档)。

## 内联段落密码

在文章或页面正文中，使用 `{password:密码}` 与 `{/password}` 包裹需要局部加密的段落：

```markdown
这是公开可见的正文段落。

{password:your-section-password}
这部分内容需要输入段落密码 `your-section-password` 才能查看。
支持包含多行文本、Markdown 语法、图片和代码块。
{/password}

这又是公开可见的正文段落。

{password:another-section-password}
这是同一篇文章中另一个独立验证的加密段落。
{/password}
```

- 同一篇文章可包含多个内联密码块，每个密码块独立验证、独立保存解锁状态。
- 文章作者本人登录后，可直接查看自己文章中的所有内联密码块。
- 在文章列表摘要、SEO 描述（`meta description`）、Open Graph 分享图提取及 RSS/Atom 订阅源中，内联密码块内容会被自动剥离。
- **标记闭合与渲染安全**：保护标记支持嵌套，但必须按顺序成对闭合。若存在未闭合、错序或语法损坏的标记，解析器将按**保密优先（Fail-Closed）**原则从对应开启位置停止输出后续公开内容。块内的 Markdown 脚注与引用链接定义会在 Markdown 渲染前一并剥离，建议发布前使用未登录的隐私窗口预览检查。

## 解锁票据与权限机制

- **签名票据**：密码验证通过后，浏览器会保存一枚由 Typecho 随机站点 `secret` 签名、有效期为 **7 天**的 `v2` HMAC 解锁票据。
- **自动失效**：票据与当前生效的密码及过期时间戳强绑定；一旦票据到期、管理员修改了对应密码或轮换了站点 `secret`，旧票据将立即失效。若站点缺失随机 `secret`，主题将拒绝签发任何解锁票据。
- **作用域隔离**：单篇文章、分类、全站与内联段落各自使用独立的 Cookie 名称存储票据，互不覆盖；非 ASCII 字符（如中文）的分类缩略名会自动附加哈希前缀以保证隔离性。
- **Cookie 与 CSRF 防护**：解锁 Cookie 默认启用 `HttpOnly` 与 `SameSite=Lax`，在 HTTPS 请求下同时启用 `Secure`。页面级与内联密码提交表单均强制校验匿名双提交 CSRF Cookie（`bold_password_csrf`）及绑定当前页面 / 段落上下文的防伪令牌。
- **免密权限边界**：仅已登录且具备**编辑（`editor`）及以上**权限的用户可免密跳过页面级密码门禁（普通订阅者或贡献者不可绕过）；内联密码块与「评论后可见」则仅允许文章作者本人免密查看。

关于 `{hide}` 评论后可见的签名回执校验机制，请参阅 [内容与页面用法](usage.md#评论后可见)；旧版升级时的票据兼容性变化请参阅 [安装与升级](installation.md#历史版本兼容性说明)。

## RSS/Atom 订阅源保护

后台选项 **「RSS/Atom 订阅源中的加密文章」**（`protectFeed`）默认开启，保护范围涵盖全站主 Feed、分类 Feed、单篇文章评论 Feed 以及全站评论总 Feed（`/feed/comments/`）：

1. **受保护文章脱敏**：凡受全站、分类或自定义字段 `password` 保护的文章，其在 Feed 中的正文与摘要均会被替换为密码保护提示。
2. **内联标记剥离**：所有文章中的 `{hide}` 与 `{password:...}` 块均在 Markdown 渲染前剥离，确保内联明文密码、隐藏内容、块内脚注及引用链接不会进入 XML。
3. **评论与频道元数据脱敏**：受保护文章下的评论在 Feed 中不仅隐藏正文，还会对评论者昵称、邮箱、个人网站、发布时间及锚点链接进行匿名化处理；单篇文章评论 Feed 的频道级描述（`channel description`）同样经过脱敏重建。

> **注意**：若将 `protectFeed` 设为「不保护（`0`）」，将取消整篇文章及受保护评论在 Feed 中的脱敏（但正文中的 `{hide}` / `{password:...}` 内联块及频道描述中的标记剥离依然保留）。此外，文章标题、发布时间与固定链接属于公开路由元数据，请勿在文章标题或 URL 缩略名中放置敏感信息。

## 缓存策略与安全边界

- **防缓存串号**：受密码保护的页面以及可能随解锁 Cookie 动态变化的列表页，均会在响应输出前发送 `Cache-Control: private, no-store` 与 `Vary: Cookie` 响应头。若站点接入了 CDN 或反向代理整页缓存，请确认上游配置遵循上述响应头，并在升级或修改密码后主动清理 HTML 与 Feed 缓存。
- **应用层保护边界**：主题提供的密码门禁属于 PHP 应用层访问控制，数据库记录、备份文件及后台设置中仍保存原文与密码。上传至公开目录的静态附件（如图片、压缩包）若知道直接 URL 仍可被直接请求，如有高敏需求请在 Web 服务器层单独配置访问控制。
- **防暴力破解建议**：主题在密码校验失败时使用了 `hash_equals` 恒定时间比较与随机微延迟以抬高在线猜测成本，但未内置跨请求的持久化 IP 限流器。生产环境请务必启用 **HTTPS**、设置高熵强密码，并在 Nginx / WAF / Cloudflare 层为 POST 请求配置速率限制。

历史安全审计发现、修复实现与完整验收记录请参阅 [安全审计记录](../security.md)。
